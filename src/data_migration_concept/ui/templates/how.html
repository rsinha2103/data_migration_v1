The ideas behind it

  • Project - a folder with all your settings. Object - one thing you migrate (suppliers, materials). Structure - one target layout of an object (general data, bank details).
  • Source - where legacy data comes from: a CSV, Excel or Parquet file you upload, or a database table.
  • Mapping - for every target field, a rule: move a column, set a fixed value, translate through a value list (XREF), join or cut text, or write SQL.
  • XREF - a two-column list that translates legacy values into target values, for example country codes. Unlisted values stop the transform so nothing is silently wrong.
  • Checks - rules the target data must satisfy. A failing error check blocks the load; a warning only reports.
  • Reconciliation - after the load, proof that nothing was lost or changed: counts, keys, totals and values compared between source and target.
  • Every row keeps its original row number, so each rejected row can be traced back to the source file.

A typical session

  1. Create a project, then add an object by uploading a file. A first mapping that moves every column is created for you.
  2. Press Extract and look at the staged data and the column profile.
  3. Edit the mapping (rename fields, add XREF translations, fixed values), add checks, then press Transform and Check.
  4. Fix what the checks found (in the source file or the rules) and repeat until nothing blocks.
  5. Add a load destination, press Load, then Reconcile and Report.

All data and settings stay on this computer. Pages and files are only reachable from localhost.
